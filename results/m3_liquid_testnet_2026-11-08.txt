The escrows on the real Liquid testnet, and the hostile peer's full set of attacks, 2026-11-08.

1. Liquid testnet (tools/liquid/t18_liquid.py, run from the PC with scripts/liquid_pc.sh run): an Elements 23.3.4
node on liquidtestnet in WSL, pruned, its wallet funded from the public faucet (0.003 L-BTC); pots divided by
SCALE=10. Each step is a real transaction sent to the node and checked by its own script engine: the funding output
(the scoped key alone cannot move it; the wallet-alone fallback refused before its height, accepted after it), the
incident transaction (scoped key + an 11-of-21 FROST co-signature, three MuSig2 pot outputs, an explicit fee
output), the pre-signed set with Liquid's explicit fee outputs (14 payouts + the bounty fan-out), a payout completed
with another outcome's attestation rejected by the node, the deposit and reward paid by the threshold attestation,
bounty slices paid by their own attestations, and a bond: the cold key alone cannot withdraw, the pre-signed
forfeiture completes with the pool's co-signature once the outcome is final. 15 passed, 0 failed.
Liquid mainnet is refused by tools/liquid/el.py. Only the escrows run on Liquid here; the daemon still runs on
Bitcoin (signet).

2. Hostile peer (examples/rogue.rs, build 3c8cea0, run with sh scripts/net_pc.sh attack: a lone Core on 7790, two
rounds). The 2026-11-07 run stopped at the flood: on WSL1 a write blocked on a link the Core had cut was never woken.
The rogue now gives up a write after 15 s. Every attack ran, the connection storm included: 9 passed, 0 failed in
each round (18/0). The Core's own log names the reasons it cut each link: 'message longer than the limit', 'too many
malformed lines', 'flooding (new messages above the rate limit)'.
